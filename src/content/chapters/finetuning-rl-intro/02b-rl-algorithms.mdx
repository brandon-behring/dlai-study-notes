<NarrativeBox title="Where we are">
Chapter 2a covered supervised fine-tuning — stable imitation bounded by demonstration
quality. This chapter is the RL half: how a model learns from a **scalar reward on its own
outputs** rather than from gold targets. We build up from reward signals to the RLHF
objective, then to the PPO → GRPO algorithm line that powers today's reasoning models.
</NarrativeBox>

## Reward signals: verifiers and reward models

[RL](../glossary#term-rl) needs something to score the model's own generations. Two kinds:

- **Verifiers** — deterministic checks ("is this math answer correct?", "does the code
  pass?"). No ambiguity, no gaming surface. DeepSeek R1 Zero famously used just two:
  math correctness and format compliance.
- [Reward models](../glossary#term-reward-model) — neural nets trained on human
  **preference pairs** to score open-ended outputs where no verifier exists.

<ConceptBox title="Bradley-Terry preference loss">
Given a preferred output $y_w$ and a dispreferred $y_l$ for the same prompt, a
[reward model](../glossary#term-bradley-terry) is trained to score $y_w$ higher:

$$
\mathcal{L}_{\text{RM}} = -\log\,\sigma\!\bigl(r_\theta(y_w) - r_\theta(y_l)\bigr)
$$

It never predicts an absolute "goodness" — only **relative** preference, which is all
humans can reliably annotate.
</ConceptBox>

[DPO](../glossary#term-dpo) (Direct Preference Optimization) takes a shortcut: it
**skips the reward model entirely** and trains the policy directly on `chosen`/`rejected`
pairs, with an implicit KL term (strength $\beta$) to a reference. One model, one fixed
dataset, no RL loop.

<Aside category="crossref">
**DPO is *offline*** — a fixed preference dataset, trained once. **PPO/GRPO are *online*** —
they generate fresh rollouts from the current policy during training and score them live.
That online/offline split is the cleanest way to file the algorithms in your head.
</Aside>

## The RLHF objective

When you *do* run the online loop, the [RLHF](../glossary#term-rlhf) objective is reward
maximization **regularized toward a reference**:

$$
\max_\theta\; \mathbb{E}_{x \sim D,\; y \sim \pi_\theta(\cdot|x)}
\Bigl[\, r_\phi(x, y) \;-\; \beta\,\mathrm{KL}\bigl(\pi_\theta(\cdot|x)\,\|\,\pi_{\text{ref}}(\cdot|x)\bigr) \,\Bigr]
$$

The [KL penalty](../glossary#term-kl-divergence) (coefficient $\beta$) is load-bearing: it
keeps the policy close to the frozen reference $\pi_{\text{ref}}$, guarding against
[reward hacking](../glossary#term-reward-hacking) and mode collapse. Too small and the
policy drifts into degenerate high-reward regions; too large and it never improves.

<KeyConcept title="The four models of RLHF" los="FRI-2.5">
Full PPO-based RLHF holds **four models** in memory at once:

1. **Policy** $\pi_\theta$ — the LLM being trained.
2. **Reference** $\pi_{\text{ref}}$ — a frozen copy, for the KL term.
3. **Reward model** $r_\phi$ — scores generated outputs.
4. **Value model** (critic) — estimates expected future reward for [advantage](../glossary#term-advantage) estimation.

**Why it matters:** four 7B+ models is enormous memory pressure — the primary reason the
field moved toward GRPO, which drops the critic. <EvidenceTag kind="verified" />
</KeyConcept>

<Aside category="interview">
"RLHF requires four models in GPU memory simultaneously — name them" is a frequent frontier-lab
screen. Miss the **reference** model (the one people forget) and it reads as never having
implemented it.
</Aside>

## PPO and GRPO

[PPO](../glossary#term-ppo) (the algorithm behind ChatGPT's RLHF) updates the policy with a
**clipped** surrogate objective so a single step can't move too far:

$$
\mathcal{L}^{\text{PPO}} = \min\!\Bigl(\rho_t\,\hat{A}_t,\; \mathrm{clip}(\rho_t,\,1-\epsilon,\,1+\epsilon)\,\hat{A}_t\Bigr),
\quad \rho_t = \frac{\pi_\theta(a|s)}{\pi_{\text{old}}(a|s)}
$$

The probability ratio $\rho_t$ measures how much the new policy changed; **clipping**
(typically $\epsilon = 0.2$) caps it near 1.0 for stability. PPO uses **GAE** for
token-level credit assignment — and a learned **critic**, the 4th model.

[GRPO](../glossary#term-grpo) (DeepSeek's algorithm for R1) removes the critic. For each
prompt it samples a **group** of $G$ outputs and uses the group mean as the baseline:

$$
\hat{A}_i = r(y_i) - \frac{1}{G}\sum_{j=1}^{G} r(y_j)
$$

Each output's advantage is simply how much better than its peers it scored — **no value
model**, so memory drops from four models to three.

<WorkedExample id="grpo-advantage" title="Worked example: a GRPO advantage update">
A prompt is rolled out $G=4$ times against a math verifier (reward 1 = correct, 0 = wrong).
Rewards: $r = [1, 0, 1, 0]$.

Group baseline $= \frac14(1+0+1+0) = 0.5$. Advantages:

$$
\hat{A} = [\,1{-}0.5,\; 0{-}0.5,\; 1{-}0.5,\; 0{-}0.5\,] = [\,+0.5,\; -0.5,\; +0.5,\; -0.5\,]
$$

The two correct rollouts get a **positive** push (make these more likely), the two wrong
ones a **negative** push — all measured *relative to the group*, with no critic to train.
Note the failure mode: if all four rollouts score the same (all right or all wrong), every
advantage is **0** and the prompt contributes no gradient — which is why GRPO needs prompts
of intermediate difficulty to learn efficiently.
</WorkedExample>

### PPO vs GRPO

| Aspect | PPO | GRPO |
|---|---|---|
| Advantage | Learned critic (GAE) | Group-mean baseline |
| Credit assignment | Token-level | Sequence-level |
| Models in memory | 4 (policy, ref, reward, critic) | 3 (policy, ref, reward) |
| Complexity | Higher | Lower |
| Notable use | ChatGPT | DeepSeek-R1 |
| Reward | Reward model | Verifiers or reward model |

<DecisionTree title="PPO vs GRPO">
- **Need token-level credit (long-form generation)?** → **PPO** with GAE.
- **Memory-constrained (can't fit four models)?** → **GRPO** (drops the critic).
- **Verifiable rewards (math, code)?** → **GRPO with verifiers** — the DeepSeek R1 recipe.
- **General-purpose assistant with a learned reward model?** → **PPO** remains the proven path.
- **Want simplicity/stability?** → **GRPO** — the field is trending toward simpler algorithms.
</DecisionTree>

<Newthought>Beyond PPO and GRPO</Newthought>, the 2025–2026 landscape has proliferated:
**DAPO** (decoupled clipping, dynamic sampling), **KTO** (preferences from single
thumbs-up/down labels, no pairs), **SimPO** (reference-free), and the broader **RLVR**
(RL with verifiable rewards) paradigm. They mostly vary three axes you now have the tools to
read: the *reward source*, the *baseline*, and *online vs offline*.

## Mode collapse

<RedFlag title="Mode collapse">
In RL training the policy can converge to a single high-reward output pattern, losing
diversity — every response becomes nearly identical (the "hello hello hello" failure from
Chapter 1 is the degenerate case).

**Why:** unconstrained reward maximization has no incentive to stay diverse; the easiest way
to raise average reward is to collapse onto the single highest-scoring mode.

**Mitigations:** the **KL penalty** against the reference (RLHF/PPO), an **entropy bonus**,
or **group-relative** methods (GRPO) whose within-group comparison preserves spread. This is
the RL cousin of [catastrophic forgetting](../02a-supervised-finetuning/) (the SFT-side
failure from Chapter 2a) — both are *loss of generality*, one from reward pressure, one from
narrow-data overwriting. <EvidenceTag kind="verified" />
</RedFlag>

## Where practitioners disagree

**GRPO ≈ DPO?** Recent analysis argues GRPO and DPO optimize closely related objectives —
both push probability mass toward preferred outputs and away from dispreferred ones — and the
practical gap is mostly **online vs offline**: GRPO samples fresh rollouts each step, DPO
trains once on a fixed preference set. So "which is better" is less a clean algorithmic win
than a question of whether you can afford an online loop and have a live grader.
<EvidenceTag kind="inference" /> A second open question is **how far RL can push a base
model**: there is evidence that RL largely *elicits* capabilities already latent in the base
model rather than creating new ones — which would make base-model choice, not the RL
algorithm, the dominant lever. In an interview, name the *axis* (online/offline, reward
source, latent-vs-new capability) rather than declaring a winner.

</SelfCheck>

$-\beta\,\mathrm{KL}(\pi_\theta \| \pi_{\text{ref}})$ keeps the policy near the frozen reference, guarding against reward hacking and mode collapse. Too small → the policy drifts and games the reward; too large → it can't improve.
</SelfCheck>

</SelfCheck>

## Summary

RL post-training optimizes a scalar reward on the model's own generations, regularized toward
a reference by a KL penalty. Rewards come from deterministic verifiers (clean, ungameable) or
learned reward models trained with the Bradley-Terry preference loss; DPO skips the reward
model and trains offline on preference pairs. The online algorithms trade off along clear
axes: PPO uses a learned critic for token-level credit (four models), GRPO replaces the critic
with a group-mean baseline (three models, sequence-level) and powers verifier-driven reasoning
models like DeepSeek R1. The recurring failure mode is mode collapse — loss of diversity under
reward pressure — held off by the KL penalty, entropy bonuses, and group-relative comparison.
That completes the core mechanics; later chapters turn to evaluation, data, and production.
