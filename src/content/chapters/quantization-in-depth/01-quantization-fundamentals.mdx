This is the foundation chapter. Before we can build quantizers or pack weights,
we must understand *what* linear quantization does mathematically and
*why* the two-parameter mapping (scale and zero point) is the backbone
of all modern weight compression. Every subsequent chapter builds on the
quantize/dequantize round-trip introduced here.

&lt;!–MDXB-8-CLOSE–&gt;

# What Is Quantization and Why It Matters

&lt;!–MDXB-9-OPEN–&gt;

**What**: Quantization maps model parameters from a high-precision
representation (e.g., FP32) to a lower-precision one (e.g., INT8). The goal
is to shrink model size and unlock faster integer arithmetic without
destroying model quality.  
**Why**: A 7B-parameter model in FP32 requires 28 GB of RAM.
Quantizing weights to INT8 cuts that to 7 GB—within reach of consumer
GPUs. Memory bandwidth is the primary bottleneck for LLM inference, so
smaller representations directly translate to higher throughput.

&lt;!–MDXB-9-CLOSE–&gt;



<Sidenote category="interview">"Why quantize?" Answer: memory bandwidth is the bottleneck for autoregressive decoding; INT8 weights move 4x faster than FP32.</Sidenote>



Model compression techniques form a hierarchy of invasiveness:

1.  **Quantization** — represent parameters in lower precision

2.  **Knowledge distillation** — train a smaller student from a larger teacher<Citation src="hinton2015distilling" />

3.  **Pruning** — remove connections (weights) to increase sparsity<Citation src="han2015deep" />

Quantization is the least invasive: it requires no retraining and can be
applied post-training to any model with linear layers. You can quantize
*weights* (the learned parameters), *activations* (the intermediate
hidden states), or both. Post-training quantization (PTQ) is the focus of
this course.

# The Linear Quantization Formula

&lt;!–MDXB-10-OPEN–&gt;

**What**: Linear quantization uses two parameters—scale *s* and zero
point *z*—to define a mapping between the original floating-point range and
the quantized integer range.  
**Why**: The linear mapping is simple, invertible (up to rounding error),
and requires storing only two extra numbers per quantized group.

&lt;!–MDXB-10-CLOSE–&gt;



<Sidenote category="warning">Always cast q to float *before* subtracting $z$. Two INT8 values subtracted can overflow: $(-128) - 1 = 127$ in signed int8.</Sidenote>



The fundamental relationship<Citation src="jacob2018quantization" /> is:

*r* = *s* ⋅ (*q* − *z*)

where *r* is the original (dequantized) value, *q* is the quantized integer,
*s* is the scale (same dtype as *r*), and *z* is the zero point (same dtype
as *q*).

To **quantize** (float → int):
$$q = \mathrm{round}\\\left(\frac{r}{s} + z\right), \quad
q = \mathrm{clamp}(q,\\ q\_{\min},\\ q\_{\max})$$

To **dequantize** (int → float):
*r̂* = *s* ⋅ (*q*<sub>float</sub> − *z*)

The quantization error is the distance between the original tensor and its
dequantized reconstruction: ∥*r* − *r̂*∥.



```cypher
import torch

def linear_q_with_scale_and_zero_point(tensor, scale, zero_point,
                                        dtype=torch.int8):
    scaled = tensor / scale + zero_point
    rounded = torch.round(scaled)
    q_min = torch.iinfo(dtype).min
    q_max = torch.iinfo(dtype).max
    q_tensor = rounded.clamp(q_min, q_max).to(dtype)
    return q_tensor

def linear_dequantization(q_tensor, scale, zero_point):
    return scale * (q_tensor.float() - zero_point)
```



# Deriving Scale and Zero Point



<Sidenote category="pattern">Derivation pattern: two unknowns ($s$, $z$), two constraints ($r_\{\}  q_\{\}$, $r_\{\}  q_\{\}$). Solve the system algebraically.</Sidenote>



Given the constraints *r*<sub>min</sub> = *s*(*q*<sub>min</sub> − *z*) and
*r*<sub>max</sub> = *s*(*q*<sub>max</sub> − *z*), subtract the first from the second:

$$s = \frac{r\_{\max} - r\_{\min}}{q\_{\max} - q\_{\min}}$$

Then substitute back to get the zero point:

$$z = \mathrm{round}\\\left(q\_{\min} - \frac{r\_{\min}}{s}\right)$$

The zero point must be clamped to \[*q*<sub>min</sub>, *q*<sub>max</sub>\] to prevent overflow
when cast to the quantized dtype.

&lt;!–MDXB-13-OPEN–&gt;

**Core Insight:** The zero point *z* is stored in the quantized dtype
(e.g., INT8). If the computed *z* falls outside \[*q*<sub>min</sub>, *q*<sub>max</sub>\], it
must be clamped to avoid integer overflow. This clamping preserves the
property that floating-point zero maps exactly to integer *z*.

**Why It Matters:** Exact zero mapping is critical for zero-padded
activations and sparse weight matrices—quantization should not introduce
bias at zero.

**When It Breaks:** Clamping introduces a small distortion in the
mapping. For tensors with extreme asymmetry, this distortion can increase
quantization error.

&lt;!–MDXB-13-CLOSE–&gt;



```cypher
def get_q_scale_and_zero_point(tensor, dtype=torch.int8):
    q_min, q_max = torch.iinfo(dtype).min, torch.iinfo(dtype).max
    r_min, r_max = tensor.min().item(), tensor.max().item()

    scale = (r_max - r_min) / (q_max - q_min)
    zero_point = q_min - (r_min / scale)

    # Clamp to valid quantized range
    if zero_point < q_min:
        zero_point = q_min
    elif zero_point > q_max:
        zero_point = q_max
    else:
        zero_point = int(round(zero_point))
    return scale, zero_point
```

# Symmetric vs Asymmetric Modes

&lt;!–MDXB-11-OPEN–&gt;

**Asymmetric mode**: maps \[*r*<sub>min</sub>, *r*<sub>max</sub>\] to
\[*q*<sub>min</sub>, *q*<sub>max</sub>\]. Uses both *s* and *z*. Fully utilizes the
quantized range.  
**Symmetric mode**: maps \[−\|*r*\|<sub>max</sub>, \|*r*\|<sub>max</sub>\] to
\[−*q*<sub>max</sub>, *q*<sub>max</sub>\]. Zero point is always zero, so the formula
simplifies to *q* = round(*r*/*s*).

&lt;!–MDXB-11-CLOSE–&gt;



<Sidenote category="interview">"When do you use symmetric vs asymmetric?" Symmetric for INT8 weights (simpler, no $z$). Asymmetric for low-bit (2–4 bit) where range utilization matters.</Sidenote>



In symmetric mode the scale simplifies to:

$$s = \frac{\|r\|\_{\max}}{q\_{\max}} = \frac{\max(\|r\|)}{127} \quad \text{(for INT8)}$$

&lt;!–MDXB-14-OPEN–&gt;

**Core Insight:** Symmetric mode sacrifices range utilization for
simplicity and memory savings (no zero point to store). Asymmetric mode
fully uses the quantized range but requires storing and computing with *z*.

**Why It Matters:** For distributions biased toward one side (e.g.,
ReLU outputs are always positive), symmetric mode wastes half the quantized
range on values that never occur. Asymmetric mode avoids this waste.

**When It Breaks:** At 8-bit precision the wasted range is tolerable,
so symmetric mode dominates in practice. At 2–4 bits, every bin matters
and asymmetric mode becomes essential.

&lt;!–MDXB-14-CLOSE–&gt;

&lt;!–MDXB-15-OPEN–&gt;

**Why interviewers ask this:** Apple MLX, NVIDIA TensorRT, Google
on-device ML, and Meta inference teams (L4–L6) ask “Derive the linear
quantization formula” or “When would you use symmetric vs. asymmetric
quantization?” This is a gating question for any ML systems or inference
optimization role—expect it in 80%+ of quantization-focused loops.

**What they’re really testing:** Whether you can write
*q* = round(*r*/*s* + *z*) from memory and explain each term.
The impressive answer derives scale and zero point from the range
mapping, explains why symmetric mode wastes half the range for ReLU
outputs, and states the bit-width threshold where asymmetric becomes
essential (4-bit and below).

**Expected depth by level:**

- **IC3/IC4:** Write the quantize/dequantize formulas.
  Explain scale, zero point, and clamping. State INT8 range
  \[−128, 127\]. Know symmetric vs. asymmetric tradeoff.

- **IC5+/Staff:** Calculate quantization error for a given
  weight distribution, explain why outliers disproportionately
  degrade accuracy, and discuss calibration strategies
  (min-max, percentile, entropy-based).

**Red flag:** Not knowing that zero point must be clamped to the
quantized dtype range. This is a subtle but critical implementation
detail that causes silent accuracy degradation in production.

&lt;!–MDXB-15-CLOSE–&gt;



```cypher
def get_q_scale_symmetric(tensor, dtype=torch.int8):
    r_max = tensor.abs().max().item()
    q_max = torch.iinfo(dtype).max
    return r_max / q_max

def linear_q_symmetric(tensor, dtype=torch.int8):
    scale = get_q_scale_symmetric(tensor, dtype)
    quantized = linear_q_with_scale_and_zero_point(
        tensor, scale, zero_point=0, dtype=dtype
    )
    return quantized, scale
```



# Quantization Error and the Round-Trip



<Sidenote category="formula">Quantization error: $ = 1\{n\}|r_i - r_i|$. With optimal $s,z$ for INT8, expect $  s/2$ per element.</Sidenote>



The round-trip—quantize then dequantize—introduces error because
is a lossy operation<Citation src="nagel2021whitepaper" />. The error depends on two factors:

1.  **Bit width**: More bits ⇒ smaller bins ⇒
    less rounding error.

2.  **Scale/zero-point optimality**: Random *s* and *z* produce
    large errors; the derived values minimize error.



```cypher
# Full round-trip demonstration
test_tensor = torch.tensor(
    [[191.6, -13.5, 728.6],
     [92.14, 295.5, -184],
     [0,     684.6, 245.5]]
)

scale, zp = get_q_scale_and_zero_point(test_tensor)
q = linear_q_with_scale_and_zero_point(test_tensor, scale, zp)
dq = linear_dequantization(q, scale, zp)
error = (test_tensor - dq).abs().mean().item()
print(f"Scale: {scale:.2f}, ZP: {zp}, Mean abs error: {error:.2f}")
# Scale: 3.58, ZP: -77, Mean abs error: ~1.0
```

&lt;!–MDXB-16-OPEN–&gt;

A tensor has values in \[−20, 100\]. You are quantizing to INT8
(*q*<sub>min</sub> = −128, *q*<sub>max</sub> = 127). Compute the scale *s* and zero point *z*
by hand. Then quantize the value *r* = 50 and verify by dequantizing.

&lt;!–MDXB-16-CLOSE–&gt;

&lt;!–MDXB-19-OPEN–&gt;

**Approach:**
**Step 1: Scale.**
$s = \frac{100 - (-20)}{127 - (-128)} = \frac{120}{255} \approx 0.471$

**Step 2: Zero point.**
*z* = round(−128 − (−20/0.471)) = round(−128 + 42.5) = round(−85.5) = −86

**Step 3: Quantize *r* = 50.**
*q* = round(50/0.471 + (−86)) = round(106.2 − 86) = round(20.2) = 20

**Step 4: Dequantize.**
*r̂* = 0.471 ⋅ (20 − (−86)) = 0.471 ⋅ 106 = 49.9

**Key Insight:** The round-trip error is \|50 − 49.9\| = 0.1, which is
well within the expected error of *s*/2 ≈ 0.24 per element.

**Answer:** The round-trip error is \|50 − 49.9\| = 0.1, which is
well within the expected error of *s*/2 ≈ 0.24 per element.

&lt;!–MDXB-17-OPEN–&gt;

A ReLU activation produces values in \[0, 6.0\]. Quantize this range to
INT8 using both symmetric and asymmetric modes. Which mode has lower
quantization error and why?

&lt;!–MDXB-17-CLOSE–&gt;

&lt;!–MDXB-20-OPEN–&gt;

**Approach:**
**Asymmetric mode:**
$s = \frac{6.0 - 0}{127 - (-128)} = \frac{6.0}{255} = 0.0235$.  
All 255 bins cover the actual data range \[0, 6.0\].

**Symmetric mode:**
$s = \frac{6.0}{127} = 0.0472$.  
The range \[−6.0, 6.0\] maps to \[−127, 127\], but values in \[−6.0, 0)
never occur. Half the 254 bins are wasted.

**Key Insight:** Asymmetric mode has roughly half the scale (twice the
precision) because it does not waste bins on negative values that ReLU never
produces. For all-positive distributions, asymmetric mode is strictly better.

**Answer:** Asymmetric mode has roughly half the scale (twice the
precision) because it does not waste bins on negative values that ReLU never
produces.

&lt;!–MDXB-18-OPEN–&gt;

A weight tensor is quantized to INT8 using symmetric mode with scale
*s* = 0.05. Derive a tight upper bound on the absolute quantization error
for any single element. Then calculate the expected mean squared error
if the rounding errors are uniformly distributed in \[−*s*/2, *s*/2\].

&lt;!–MDXB-18-CLOSE–&gt;

&lt;!–MDXB-21-OPEN–&gt;

**Approach:**
**Upper bound:** Rounding maps each real value to the nearest integer.
The maximum rounding error is 0.5 in quantized units, which in real units is
\|*r* − *r̂*\| ≤ *s*/2 = 0.05/2 = 0.025.

**MSE derivation:** If the rounding error *ϵ* is uniform on
\[−*s*/2, *s*/2\], then $\text{MSE} = \mathbb{E}\[\epsilon^2\] = \frac{s^2}{12}
= \frac{0.05^2}{12} = \frac{0.0025}{12} \approx 2.08 \times 10^{-4}$.

**Key Insight:** Quantization error scales as *s*<sup>2</sup>/12. Halving the
scale (doubling the precision) reduces MSE by 4×. This is why
moving from INT8 to INT4 roughly quadruples the per-element error—the
scale doubles to cover the same range with fewer bins.

**Answer:** Quantization error scales as *s*<sup>2</sup>/12. Halving the
scale (doubling the precision) reduces MSE by 4×.
