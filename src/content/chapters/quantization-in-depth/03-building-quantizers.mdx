# The W8A16 Forward Method

&lt;!–MDXB-10-OPEN–&gt;

**What**: The forward pass of a W8A16 layer casts INT8 weights to the
input’s dtype, performs the matmul, multiplies by the per-channel scale, and
optionally adds bias.  
**Why**: This separates the *storage* format (INT8) from the
*compute* format (FP16/FP32), keeping the arithmetic numerically stable
while benefiting from compressed storage.

&lt;!–MDXB-10-CLOSE–&gt;



<Sidenote category="pattern">W8A16 forward pattern: (1) cast INT8 weights to input dtype, (2) F.linear(input, casted_weights), (3) multiply by scales, (4) add bias.</Sidenote>





<Sidenote category="interview">"Why not do matmul directly in INT8?" Because standard GPU matmul kernels accumulate in FP32. Direct INT8 matmul requires specialized kernels (cuBLAS INT8 GEMM) and W8A8 quantization of activations.</Sidenote>





```cypher
import torch
import torch.nn as nn
import torch.nn.functional as F

def w8a16_forward(int8_weights, input, scales, bias=None):
    """Cast INT8 weights to input dtype, matmul, scale, add bias."""
    casted_weights = int8_weights.to(input.dtype)
    output = F.linear(input, casted_weights)
    output = output * scales
    if bias is not None:
        output = output + bias
    return output

# Quick test
int8_w = torch.randint(-128, 127, (32, 16), dtype=torch.int8)
hidden = torch.randn(1, 10, 16)
scales = torch.randn(32)
out = w8a16_forward(int8_w, hidden, scales)
print(f"Output shape: {out.shape}")  # (1, 10, 32)
```





<Sidenote category="formula">Shape check: weights $(O, I)$, input $(B, S, I)$, output $(B, S, O)$. Scales must be shape $(O,)$ to broadcast.</Sidenote>



# Building the W8A16LinearLayer Class

&lt;!–MDXB-14-OPEN–&gt;

**Core Insight:** PyTorch’s requires tensors that
support gradient computation. INT8 tensors cannot have gradients, so
attempting raises
an error. Use instead: it stores the tensor on the
module (participates in , moves with ),
but does not require gradients.

**Why It Matters:** This distinction is the single most common error
when building custom quantized layers. Every quantization library
(bitsandbytes, GPTQ<Citation src="dettmers2022gptq" />, AWQ) uses buffers for integer weights.

**When It Breaks:** Buffers are *not* returned by
, so optimizers will not update them. This is
intentional for inference-only quantized weights but must be accounted for
if you later want quantization-aware training.

&lt;!–MDXB-14-CLOSE–&gt;



<Sidenote category="warning">nn.Parameter on INT8 tensors raises: "only tensors of floating point and complex dtype can require gradients." Always use register_buffer for quantized weights.</Sidenote>





```cypher
class W8A16LinearLayer(nn.Module):
    def __init__(self, in_features, out_features,
                 bias=True, dtype=torch.float32):
        super().__init__()
        self.register_buffer(
            "int8_weights",
            torch.zeros(out_features, in_features, dtype=torch.int8)
        )
        self.register_buffer(
            "scales",
            torch.zeros(out_features, dtype=dtype)
        )
        if bias:
            self.register_buffer(
                "bias",
                torch.zeros(out_features, dtype=dtype)
            )
        else:
            self.bias = None

    def quantize(self, weights):
        """Quantize FP weights into INT8 using per-channel symmetric."""
        w_fp32 = weights.float()
        scales = w_fp32.abs().max(dim=-1, keepdim=True).values / 127
        scales = scales.to(weights.dtype)

        int8_weights = torch.round(w_fp32 / scales).clamp(
            -128, 127
        ).to(torch.int8)

        self.int8_weights = int8_weights
        self.scales = scales.squeeze()

    def forward(self, input):
        return w8a16_forward(
            self.int8_weights, input, self.scales, self.bias
        )

# Test
layer = W8A16LinearLayer(16, 32)
dummy_weights = torch.randn(32, 16)
layer.quantize(dummy_weights)
out = layer(torch.randn(1, 5, 16))
print(f"Shape: {out.shape}, INT8 range: "
      f"[{layer.int8_weights.min()}, {layer.int8_weights.max()}]")
```



# Recursive Module Replacement

&lt;!–MDXB-11-OPEN–&gt;

**What**: Walk the model’s module tree recursively. For every
instance, create a with matching
dimensions, copy and quantize the old weights, then swap the module using
.  
**Why**: This decouples the quantization logic from the model
architecture. The same function works for any model—transformers, CNNs,
or multimodal—as long as it contains layers.

&lt;!–MDXB-11-CLOSE–&gt;



<Sidenote category="pattern">Recursive replacement: named_children() to iterate, isinstance() to match, setattr() to swap, recurse on non-matching children.</Sidenote>





```cypher
def replace_linear_with_target_and_quantize(
    module, target_class, module_name_to_exclude=None
):
    if module_name_to_exclude is None:
        module_name_to_exclude = []

    for name, child in module.named_children():
        if isinstance(child, nn.Linear) and \
           name not in module_name_to_exclude:

            old_bias = child.bias
            old_weight = child.weight

            new_module = target_class(
                child.in_features, child.out_features,
                bias=old_bias is not None,
                dtype=child.weight.dtype,
            )
            setattr(module, name, new_module)

            # Quantize using old weights
            getattr(module, name).quantize(old_weight)
            if old_bias is not None:
                getattr(module, name).bias = old_bias
        else:
            # Recurse into submodules
            replace_linear_with_target_and_quantize(
                child, target_class, module_name_to_exclude
            )
```





<Sidenote category="interview">"Why exclude LM head from quantization?" Its output feeds back as next-token logits. Rounding errors accumulate, causing gibberish after 50–100 tokens.</Sidenote>

# Loading Quantized Weights from the Hub

&lt;!–MDXB-16-OPEN–&gt;

**Core Insight:** PyTorch’s meta device creates tensor *skeletons*
(shape and dtype metadata) without allocating memory. This lets you
initialize the model architecture, replace linear layers with quantized
shells, then load the quantized directly—never
allocating the full-precision model.

**Why It Matters:** A 7B model in FP16 requires 14 GB just to load.
With meta device loading, you need only ∼7 GB (the INT8 state dict)
plus a small overhead for the model skeleton.

**When It Breaks:** with
requires PyTorch ≥ 2.1. Older versions do not support in-place
assignment from meta tensors.

&lt;!–MDXB-16-CLOSE–&gt;

&lt;!–MDXB-17-OPEN–&gt;

**Why interviewers ask this:** Apple MLX, NVIDIA, Google on-device,
and HuggingFace inference teams (L4–L6) ask “How would you deploy a
quantized 7B model on a single consumer GPU?” or “Walk me through
the quantize-save-load workflow.” This tests production deployment
skills—can you go from a full-precision checkpoint to a deployable
INT8 model end-to-end?

**What they’re really testing:** Whether you understand the meta
device pattern: init skeleton → replace Linear layers → load

The impressive answer explains memory savings (14 GB FP16 → 7 GB

The workflow has three stages:

1.  **Quantize on a large machine**: Load model → quantize
    → save → push to Hub.

2.  **Load skeleton on small machine**: Load config →
    init model on meta device → replace linear layers (no
    quantize step).

3.  **Load quantized weights**: Download state dict from Hub
    → .



```cypher
from transformers import AutoConfig, OPTForCausalLM
from huggingface_hub import hf_hub_download

# Step 1: Load skeleton on meta device (no RAM allocated)
config = AutoConfig.from_pretrained("facebook/opt-125m")
with torch.device("meta"):
    model = OPTForCausalLM(config)

# Step 2: Replace linear layers (without quantizing)
# Use a version of replace that does NOT call .quantize()
# (module shells only, awaiting state_dict)

# Step 3: Load quantized state dict
state_dict_path = hf_hub_download(
    "quantized-models/opt-125m-int8",
    filename="quantized_state_dict.pt"
)
state_dict = torch.load(state_dict_path, map_location="cpu")
model.load_state_dict(state_dict, strict=True, assign=True)
```

&lt;!–MDXB-20-OPEN–&gt;

**Approach:**
**Question 1:** Audio projection layers convert continuous spectral
features (mel-spectrograms) into the discrete token embedding space. These
features have high dynamic range and fine-grained magnitude differences that
carry phonetic information. INT8 quantization with 256 bins cannot preserve
the subtle differences between similar phonemes (e.g., “b” vs. “p”).
In contrast, the language decoder processes token embeddings that are already
discrete and have been trained to be robust to small perturbations. The
decoder also benefits from error correction through autoregressive
generation—a slightly wrong hidden state can be compensated by the next
token’s context. Audio projection has no such error correction.

**Question 2:**


```python
SKIP_MODULES = {"AudioEncoder", "FeatureProjection",
                "SpecAugment"}

def replace_linear_with_target(model, target_cls,
                               skip_names=None):
    skip_names = skip_names or set()
    for name, child in model.named_children():
        if type(child).__name__ in SKIP_MODULES:
            continue  # preserve in FP16
        if isinstance(child, nn.Linear):
            setattr(model, name, target_cls(child))
        else:
            replace_linear_with_target(child, target_cls,
                                       skip_names)
```



**Question 3:** Three-part evaluation:

1.  **Text-only**: Standard language modeling perplexity on text
    prompts (already passing).

2.  **Audio-only**: WER on a held-out audio test set with diverse
    accents and background noise. Threshold: WER increase  ≤ 1%
    relative to FP16.

3.  **Cross-modal**: End-to-end podcast transcription on 10
    real-world samples. Compare word-level alignments, not just
    aggregate WER, to catch hallucination patterns.

**Key Insight:** The recursive replacement pattern is powerful but
dangerous when applied blindly across modalities. The default should be
to quantize all layers and explicitly *exclude* sensitive layers
(projection, embedding, LM head), not the reverse. Always validate
each modality independently after quantization.

**Answer:** The recursive replacement pattern is powerful but
