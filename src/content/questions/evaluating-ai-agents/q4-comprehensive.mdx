answer: >
  "Comprehensive, not exhaustive" means cover every input *type* with 1–2 examples rather than
  piling up 100 near-duplicates per category. The reason is iteration speed: a small, varied
  dataset runs fast and stays cheap to maintain, so you can re-run it on every change — while
  still spanning the behaviour space enough to catch regressions. A bloated dataset slows each
  experiment and adds little new signal once a type is represented. Input keys are forwarded to
  the agent; output keys are forwarded to the evaluators for comparison. Common wrong answer:
  "more cases are always better" — past one or two per type you mostly buy slower runs, not more
  coverage.
