Why wrap LLM-as-a-judge calls in `suppress_tracing()` during a Phoenix evaluation run?

<Rationale title="Why">
The judge is itself an LLM call, so without suppression its spans land in the same trace store
and intermingle with the agent's spans — a large eval run can roughly double the store with
evaluation artifacts and corrupt trace analysis. It isn't a performance trick, it doesn't
control the output format (rails do that, set separately), and it doesn't change what the judge
reads — it only governs whether the judge's calls are *traced*.
</Rationale>
